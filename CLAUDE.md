# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

WhatTheFlight is a SwiftUI-based flight tracking application that monitors aircraft overhead using FlightRadar24 API data. The project targets iOS, macOS, and visionOS platforms and displays real-time flight information within configurable geographic bounds.

## Build & Test Commands

This is an Xcode project using standard Xcode build commands:

- **Build**: `xcodebuild -project WhatTheFlight.xcodeproj -scheme WhatTheFlight -configuration Debug build`
- **Test**: `xcodebuild -project WhatTheFlight.xcodeproj -scheme WhatTheFlight -configuration Debug test`
- **Run Tests**: `xcodebuild test -project WhatTheFlight.xcodeproj -scheme WhatTheFlight -destination 'platform=iOS Simulator,name=iPhone 15'`
- **Clean**: `xcodebuild -project WhatTheFlight.xcodeproj -scheme WhatTheFlight clean`

For development, open `WhatTheFlight.xcodeproj` in Xcode.

## iOS / iPadOS app (radar v2) — start here

On iOS the app runs the redesigned radar (`RadarRootView`, selected in `WhatTheFlightApp.swift`). macOS and tvOS still run the legacy `ContentView` stack described under "Architecture" below; those legacy files are not used on iOS.

Layout (all under `WhatTheFlight/WhatTheFlight/`):
- `Core/` — platform-neutral, unit-tested logic: `GeoMath` (distance, bearing, dead reckoning, closest approach, elevation above the horizon), `Flight` / `RadarContact`, `FlightFeedParser` (FR24 `feed.js` array format), `PerimeterTrack` (rounded-rect edge path + optimal icon spacing), `FocusPolicy` (which aircraft owns the centre), `OperatorInfo` (the line under the flight number: airline, "Private aircraft · 🇺🇸 United States", "Unlisted operator XYZ"), `NotableTraffic` (emergency squawks, military, government, air ambulance, rare types), `RouteProgress` (miles flown / to go), `SkyProjector` (pinhole camera maths for Sky View: project / unproject, `reframed` for a photo or video frame), `CameraZoom` (Sky View lens maths: field of view per zoom factor, 0.5× / 1× / 2× / 5× stops), `SkyCorrection` (Sky View visual lock-on: `SkyBlobDetector` finds the aircraft as a dot near its predicted spot, `VisualFix`, and the learned compass yaw applied to every label), `Whereabouts` ("Where is it now?" wording: in the air / on the ground at ATL, still on vs now flying, distance from you), `WristPointing` (Apple Watch Point & Find: forearm direction from attitude + wrist/crown settings, guidance, haptic cadence).
- `Data/` — offline catalogs: airlines (ICAO + radio callsign), aircraft types + helicopter detection + radar silhouettes (`AircraftTypeCatalog.silhouetteCodes` → `AircraftSilhouette`; unknown codes get the airliner), airports (IATA → city/name/coordinates), `RegistrationCountry` (tail-number prefix → country). `AirlineCatalog+Data.swift` (~5,800 rows, OpenFlights, ODbL) and `AirportCatalog+Data.swift` (~8,800 rows, OurAirports, public domain) are GENERATED by `Scripts/generate_catalogs.py`; the hand-curated lists in `AirlineCatalog.swift` / `AirportCatalog.swift` override them, so fix names there. Callsign lookup order: feed airline field → special words (`SAM`, `LIFE`, `NAVY`…) → 3-letter ICAO prefix followed by a digit.
- `Radar/RadarModel.swift` — `@Observable` state machine: polling with backoff, 1 Hz dead-reckoning tick, radius filter, focus, queued notices, per-flight trails (feed positions seen while watching, for the map). It also feeds `logbook?.record(...)` (`isLogging`: live traffic only — never demo, never an iPhone custom spot; the TV sets `logsCustomSpot` because its set place is its real location) and runs `TrafficAlertEngine`; alerts go to `onAlert` or become notices. The observer coordinate is pushed in, so it has no CoreLocation manager dependency.
- Pinning & worldwide search: one "pin" concept everywhere (hold the hero, TV ⏯ / dock, detail screens, search rows). Pins are `PinnedAircraft` (in `Core/FocusPolicy.swift`; matched by registration, else callsign, so they follow an airframe onto its next leg), stored in `RadarSettings.pinnedAircraft` (`wtf.pinnedAircraft`, JSON, max `RadarModel.maxPins` = 5; the oldest makes way with a notice). `RadarModel` looks up pins the main feed's box missed with `FlightFeed.lookup` every ~20 s (`pinnedFlights`, dead-reckoned between), so they appear in `outsideContacts` however far away; `pinnedOutside` / `perimeterContacts` put them on the radar edge, `pinnedIDs` feeds `PerimeterLayer` / `TrafficMap` (pin badge `PinMarker`, never faded). `focus.isPinned` is always derived (every focus change goes through `setFocus`). `RadarModel.searchAnywhere` → `FlightRadarFeed.search`: three parallel world `feed.js` requests (`reg=`, `flight=`, `callsign=`; FR24 filters are uppercase prefix matches, take comma lists and AND together; registrations only match with their hyphen, so `RegistrationCountry.hyphenatedForms` adds `G-XLEI` for `GXLEI`). UI: iPhone `FlightSearchSheet`, TV `TVAircraftListView` (dock → Aircraft, now `.searchable`). The map follows a far-away pinned focus on its own (`TrafficMapGeometry.followsPinnedAlone`). Pins sync across iPhone, iPad, Apple TV and Apple Watch through iCloud key-value storage (`Services/PinSync.swift`, always on, independent of the logbook switch): one key per pin (`pin.<registration|callsign|flightID>`, JSON), `wtf.pinsInCloud` remembers which ids this device has seen in iCloud so a missing key means "unpinned elsewhere" vs "not sent yet"; demo pins never sync; `pinnedAt` orders pins and the cap across devices. All three apps' entitlements set `com.apple.developer.ubiquity-kvstore-identifier` to `$(TeamIdentifierPrefix)SargeyWargey.WhatTheFlight` so they share one store; `RadarModel.pinsDidChangeElsewhere` reacts to remote changes. DEBUG: `-wtf.debugPin <query>` pins the first worldwide hit, `-wtf.debugAircraftSearch <query>` pre-fills either search screen.
- `Radar/SpotPhoto.swift` — Sky View photos: `SpotPhoto` (the aircraft and its stats at the shutter, where it sits in the frame) rides on `Sighting.photos` (merged as a union minus `removedPhotoIDs`); `SpotPhotoStore` keeps the logbook's 1600 px HEIC copy per photo in Application Support/SpotPhotos. Photographing an aircraft outside the radius still logs it (`Logbook.addPhoto`). The full-resolution original goes to the camera roll (add-only, no album, flight in IPTC caption/keywords; setting `wtf.skySaveToPhotos`).
- `Radar/Logbook.swift` — sightings persisted as JSON in Application Support, `LogbookStats`, `DailyRecap` ("Today's highlights": notable aircraft, first-of-type, new airlines), `Achievement` badges. Each `Sighting` records `devices` (`LogDevice`) and `placeName` (reverse-geocoded by `Services/PlaceNamer`, set on `RadarModel.logPlaceName`). `Services/LogbookSync` merges logbooks across iPhone / iPad / Apple TV with CloudKit `CKSyncEngine` (container `iCloud.SargeyWargey.WhatTheFlight`, zone `Logbook`, one record per flight id holding the sighting as JSON; copies merge via `Sighting.merged(with:)`; each photo's image is its own `SpotPhoto` record "photo-<id>" with a CKAsset, and `LogbookSync.downloadPhoto` fetches one on demand). Setting `wtf.iCloudLogbook`. Custom spots and demo traffic are never logged on iPhone (`RadarModel.isLogging`); the radar shows a "Custom spot · … · not logged" tag along the bottom. `Radar/TrafficAlerts.swift` — overhead (closest approach within N mi in ≤150 s) and notable alerts, once per flight per reason.
- `Services/` (new files) — `FlightFeed` (`FlightRadarFeed` + deterministic `DemoTrafficFeed`), `RadarSettings` (UserDefaults, keys prefixed `wtf.`), `RadarLocationService` (GPS + unwrapped true heading; `setBackgroundTracking` for Sky Watch), `AircraftPhotoProvider` (Planespotters.net API; requires a descriptive User-Agent and photographer credit), `SharedRadarStore` (App Group `group.SargeyWargey.WhatTheFlight`: observer, radius, `RadarSnapshot` for widgets / Siri / Top Shelf; `NearbyTraffic` one-shot fetch), `SkyServices` (Core Motion attitude → ENU basis, raise-to-look detector), `SkyCamera` (multi-lens virtual back camera with zoom, photo capture with metadata, `SkyFrameTracker` looking for the tracked aircraft in video frames), `SpotPhotoProcessing` (logbook copy, caption/keywords/GPS metadata, `PhotoLibrarySaver`, simulator `SyntheticSkyPhoto`), `SkyWatch` + `SkyWatchAttributes` (Live Activity), `AlertNotifier` (local notifications), `AppRouter` (`whattheflight://flight/<id>|sky|logbook` deep links, also used by intents), `RadarIntents` (App Intents + App Shortcuts).
- `UI/` — SwiftUI views. `RadarScreen` composes `RadarBackdrop`/`CompassBezel`, `FlightHero`, `PerimeterLayer`, status badge (tap: logbook) and settings button (Sky View has no button: lifting the phone opens it via `RaiseToSkyDetector`, as do "Find in the Sky" on a flight's details and Siri); sheets for detail (Nearby / Full Route map via `DetailMap`, route progress, "seen before"), search, settings, welcome, logbook (`LogbookView`); `SkyView` is a full-screen cover: positions dead-reckoned every frame, pinch / lens chips to zoom, a shutter that files the photo under the aircraft and opens `SpotPhotoView` (`UI/SpotCard.swift`: the boarding-pass card, rendered on demand with `SpotCardRenderer`, share / save / "Wrong aircraft?" / delete). Photos show on the sighting page, in `SpotPhotoGallery`, and on the Apple TV's sighting page in place of the Planespotters photo. First run shows the tour (`UI/Onboarding.swift`: `TourPage.all` per platform, animated `TourArt` drawings with made-up traffic, `OnboardingView` pager on iPhone; gated by `wtf.hasSeenWelcome`, replayable from Settings → "Take the tour again"). `NotableBadge` marks notable traffic. App icons: the primary `AppIcon` (iOS, light/dark/tinted) and `App Icon & Top Shelf Image` (tvOS) plus ten iPhone/iPad alternates chosen in Settings → Display → App Icon (`Services/AppIconChoice`, `UI/AppIconPicker`): `AppIcon-<name>.appiconset` with `IconPreview-<name>` images for the picker (`ASSETCATALOG_COMPILER_INCLUDE_ALL_APPICON_ASSETS` for iphoneos/iphonesimulator only). The Apple TV has no alternates: App Store Connect rejected tvOS image-stack alternates (ITMS-90471 / 90531), so don't add them back. Art sources and the previous icon live in `AppIcons/` at the repo root; DEBUG `-wtf.debugIcon <choice>` switches the icon, `-wtf.debugSheet appicon` opens the picker. `AircraftGlyph` draws the top-down aircraft silhouettes (SwiftUI shapes on a 64 × 64 grid, nose up, all drawn at the same size) used on the radar edge, maps and lists; military traffic is tinted olive (`Palette.blip(for:)`) and the helicopter rotor spins unless Reduce Motion or Always-On is on.
- iPad map pane (spec: `Ambient Map Spec.md`): in landscape at regular width with Map view on (`wtf.mapView`, Settings → Display, iPad only), `RadarRootView` puts `RadarScreen` on the left (as wide as the screen is tall) and an interactive `TrafficMap` on the right: pan/zoom, recentre button, tap a glyph to focus it, turns with the iPad's heading in 10° steps unless "Map north up" (`wtf.mapNorthUp`). Portrait, Split View and iPhone show the radar alone.
- `UI/TrafficMap.swift` — the shared ambient map (iOS + tvOS): every in-range aircraft (`AircraftBlip`, label underneath), fringe traffic up to 1.5× the radius at 40 %, the focused aircraft wherever it is, trails faded by age (`TrafficMapGeometry.segments`, rebuilt on `RadarModel.trailVersion`, i.e. per feed, not per tick), airport pins only for origins/destinations of drawn flights, the radius ring with half/quarter echoes, and a paper wash polygon over the base map (`.muted` alone barely mutes it). The camera fits the ring once and only moves for radius / place / "up" changes or to keep a pinned aircraft that left the radius in view. A turned map needs a `MapCamera` distance, which it learns from MapKit's first region fit (`metresPerMile`). It also holds the pieces `DetailMap` shares (`RadiusRings`, `ProjectedPath`, `ObserverDot`, `AirportPin`); the maths is in `Core/TrafficMapGeometry.swift` (unit-tested).

Behaviour rules (from `Working Spec.md`): the nearest aircraft takes the centre and stays there until it leaves the radius or the user swipes right; icons sit on the screen edge at their compass bearing (rotating with the phone), face their real track, never under the Dynamic Island / home indicator, with whole-mile labels between icon and centre.

### Apple TV (radar v2)
tvOS runs `TVRadarRootView` (`UI/TV/`), reusing the same model, core and visual components (`FlightHero`, `PerimeterLayer`, `RadarBackdrop` take a `scale` for the 10-foot view). "Up" on the TV is `RadarSettings.tvFacingDegrees` — the compass direction the viewer faces when watching. Remote: ◀/▶ closer/farther aircraft, click = details, play/pause = pin, ▼ = dock (Nearest, Pin, Aircraft, Settings); hints sit in a footer in the bottom overscan margin and the dock only appears after ▼. Place search is a full-screen `.searchable` with `PlaceCompleter` (MapKit `MKLocalSearchCompleter`) suggestions as you type. `TVRadarSettingsView` is a sidebar + chip-row design (tvOS has no sliders); location can come from the iPhone, MapKit place search, the Apple TV's own Wi-Fi location, or typed coordinates.

iPhone → TV link (`Services/TVLink.swift`): MultipeerConnectivity, service `wtf-radar`. The TV advertises a 4-digit code and auto-accepts; the iPhone (`UI/TVLinkSetupView.swift`, Settings → Apple TV) sends `TVLink.Payload` (lat/lon + facing) and waits for an `Ack`. Facing comes from `AimingCompass` (Core Motion attitude vs true north: back-camera direction when upright, top edge when flat). Bonjour/local-network/camera keys live in `Config/WhatTheFlight-Info.plist`, merged via `INFOPLIST_FILE`.

Ambient map (TV): with Map view on (`wtf.mapView`, default on; Settings → Display) the dock gains Map / Radar, which flips `wtf.tvView` (`radar` / `map`, remembered; read it as `settings.effectiveTVView`, which is the radar whenever Map view is off). `UI/TV/TVMapStack.swift` is the map layer `TVRadarScreen` swaps in for the radar face: full-screen `TrafficMap` turned to the TV's facing (or north up, `wtf.mapNorthUp`) plus the hero card bottom-right; the badge, hints, dock and every remote command stay in `TVRadarScreen` (`heroButton` is the focus anchor on both views; the map is disabled and never focusable). After 30 s without input the badge and hints fade (ambient settle); the first time the map opens with Keep screen awake off it posts a one-off notice (`wtf.mapAwakeHintShown`).

TV extras: the dock has a Logbook item (`TVLogbookView`), the detail screen toggles Nearby / Full Route, Radar settings include alerts (delivered as on-screen notices, and read aloud by `AlertSpeaker` when "Speak alerts" / `wtf.spokenAlerts` is on; sentences come from `SpokenTraffic` in `Radar/TrafficAlerts.swift`; while one is read out, `AlertSpeaker.speakingFlightID` pulses that aircraft purple, `Palette.announce`, on the radar edge and the map), "Alert ahead" (`wtf.overheadAlertLead`, seconds before closest approach, default 150) and the logbook switch. First run (or Settings → About → Take the tour) shows `TVOnboardingView` (`UI/TV/`), same pages and drawings with a Siri Remote page instead of Sky View; its last page goes to Settings → Location, demo traffic, or straight to the radar. `WhatTheFlightTopShelf/` is a Top Shelf extension (tvOS only) that fetches traffic around the shared observer and shows Planespotters photos; selecting an item opens `whattheflight://flight/<id>`.

### iPhone extensions & background
- `WhatTheFlightWidgets/` — widget extension (iOS only): "Overhead" widget (small, medium, Lock Screen rectangular/circular/inline) that fetches traffic itself around the shared observer, plus the Sky Watch Live Activity (Lock Screen + Dynamic Island, Stop button via `StopSkyWatchIntent`). Compiled with `WIDGET_EXTENSION`.
- Both extensions are separate targets that reuse app files through `PBXFileSystemSynchronizedBuildFileExceptionSet` membership lists on the `WhatTheFlight` folder (see project.pbxproj); a new shared file must be added there. They're embedded with platform filters (widgets → ios, Top Shelf → tvos).
- Sky Watch keeps the radar running in the background via location updates (`UIBackgroundModes: location`, blue indicator) for up to two hours; alerts then arrive as notifications. Entitlements: `WhatTheFlight-iOS.entitlements` (App Group + time-sensitive notifications), `WhatTheFlight-tvOS.entitlements` (App Group); macOS keeps `WhatTheFlight.entitlements`.
- FR24's per-flight `clickhandler` endpoint is behind a Cloudflare bot check — don't build on it. To find one aircraft anywhere, `FlightRadarFeed.locate` uses `feed.js` with world bounds plus `reg=` (or `callsign=`), ground traffic included; `WhereaboutsLookup` / `WhereaboutsMap` (`UI/WhereaboutsMap.swift`) drive the iPhone `WhereaboutsView` and `TVWhereaboutsView`, shown from a flight's details once it's outside the radius and from logbook entries. Aircraft pages show a "Logbook N" button (`LogbookCountLabel` / `TVLogbookCountLabel`, N = `Logbook.summary(airframe:).count`, all time) that opens the airframe's full log: `AirframeHistoryView` (iPhone) or `TVAirframeHistoryView` (TV). On the TV detail screen every action sits in one full-width row along the bottom. The current watch point reaches logbook screens through the `\.radarObserver` environment value.

### Apple Watch
`WhatTheFlightWatch/` is a standalone watchOS 11+ app (`WKRunsIndependentlyOfCompanionApp`, embedded in the iOS app via "Embed Watch Content" with an ios platform filter) that runs the same `RadarModel` with its own GPS (`WatchLocationService` in `WatchSensors.swift`). Spec and decisions: `Apple Watch Spec.md` at the repo root.
- `WatchRootView` is three vertical pages (`TabView` `.verticalPage`): `WatchSettingsView` above (a "Nearby aircraft" row first), the radar, `WatchNearbyList` below. No banners on the Watch: alerts are haptics only.
- `WatchRadarView`: hero + perimeter on the Watch's rounded rectangle (`WatchRadarLayout`: max 8 icons, mile labels on the nearest 4 at 40–42 mm, corner obstacles for the clock and the pointer button). Swipe left / the Digital Crown step `focusNext`, swipe right `focusPrevious`; double tap (`handGestureShortcut` on the "Nearest" button) returns to the nearest; long press on the hero pins. The only toolbar button is the pointer: tap opens Identify, hold switches Point ↔ Aim with a haptic. Wrist down (scene `.inactive`, Always-On) stops polling and GPS and `RadarModel.advanceClock()` dead-reckons once a minute.
- First run shows `WatchTourView` (`WatchTour.swift`, `wtf.watch.hasSeenTour`, replay from Settings → Take the tour) before the location prompt: quick pages for swipes/taps, then the pointer button (a working copy: tap → its page, hold → switch style), Point and Aim acted out with the real haptics and the call-out, Find (real `AzimuthStrip` / `ElevationGauge`), and a style picker with "Try Identify". DEBUG: `-wtf.debugTourPage N`.
- `WatchFlightDetail` (Handoff `NSUserActivity` `SargeyWargey.WhatTheFlight.flight` → iPhone flight details), `WatchNearbyList`, `WatchSettingsView`.
- Two aim styles for Identify and Find (setting `wtf.watch.aimStyle`, Settings → Identify & Find → Aim with, or hold the radar's pointer button): **Point** (arm out, the forearm is the pointer) and **Aim** (hold the Watch as if reading it and sight along its top edge — `WristPointing.sightLine`; turn your body, tilt your wrist; the screen faces you so watchOS doesn't dim it). A red `AimMarker` sits on the aiming edge: top for Aim, the finger side for Point.
- Both modes use `PointingLayout` (`PointingUI.swift`). Aim is always upright. In Point the content auto-rotates like a phone: its top goes to whichever screen edge is highest (`WristPointing.screenTurn` from gravity, debounced in `WristPointer.screenTurn`), so palm-down it reads toward the hand and thumb-up it runs upright along the arm. The screen-vs-Core-Motion axis sign comes from the verified arm direction (`WristPointing.displaySign`), so it follows the wrist and crown settings. "Turn screen around" (`wtf.watch.flipScreen`) adds half a turn if it still reads upside down. Nav bar hidden; watchOS keeps its clock in the screen's top-right, so `PointingMetrics` puts the close button in the free top corner and insets the bottom row / gauge. The readout shows the Watch's wrist and crown settings. Sensors via `WristPointer` (Core Motion; compass + gravity fallback; "Reverse arm direction" = `wtf.watch.flipPointing`). Only the forearm axis counts, so wrist twist doesn't matter. While either mode is open the root view keeps the radar and GPS running when the screen dims.
  - **Identify** (`IdentifyView`, the radar's hand button, Siri "Identify a plane"): names what you point at. `WristPointing.candidates` = aircraft within 15 mi (`identifyRangeMiles`; the Watch sets `RadarModel.queryRadiusFloor` so the feed covers it) and ≥ 3° up (helicopters ≥ 1°, `WristPointing.isIdentifiable`), inside a 10° cone; `IdentifyTracker` needs a 0.5 s hold, then keeps the name within 15°. Before anything's in the cone, the lead (`WristPointing.lead`: nearest the arm on the compass within 30°, sticky by 4°) is highlighted on the strip and drawn as a dashed band on the `ElevationGauge` (`isPreview`) so you can set the height while still swinging round. The strip and gauge draw each aircraft's own silhouette (`AzimuthStrip.Mark(contact:)`; on the strip it faces its track with the arm's direction up). Tick on acquire, `.success` on naming, spoken call-out (`SpokenTraffic.identification`, `IdentifySpeaker`, setting `wtf.watch.speakIdentification`). Crown cycles aircraft in the cone; tap the card for details.
  - **Find** (`PointAndFindView`, from a flight's details or the alert's "Find in the Sky"): guides you to one chosen aircraft. `AzimuthStrip` (compass strip centred on the arm) and `ElevationGauge` (horizon → zenith, aircraft band vs. arm pointer); haptics follow `WristPointing.cue` — clicks while swinging round, `.directionUp`/`.directionDown` for height, `.success` on lock.
- Settings: shared keys in `RadarSettings` (the Watch's radius defaults to 10 mi and isn't synced) plus Watch-only `WatchSettings` (`wtf.watch.*`: location source Here / iPhone's spot, north up, photos on cellular, flip pointing). No logbook on the Watch.
- `Services/WatchSync.swift` (iOS + watchOS): `PhoneWatchLink` sends `WatchSync.Context` (iPhone spot, helicopters, alert rules) as application context from `RadarRootView`; the Watch can ask the iPhone to start Sky Watch (only works while the iPhone app is in the foreground).
- Alerts: the iPhone posts category `wtf.traffic` (`TrafficNotification` keys; the aircraft rides along as a `SnapshotFlight` JSON string) with a "Find in the Sky" action. The Watch draws the long-look (`WatchNotification.swift`) and opens Point & Find from the action; on iPhone the action opens Sky View in find mode (`AppRouter.Route.find`, `whattheflight://sky/<id>`). The Sky Watch Live Activity has a `.small` layout for the Watch Smart Stack.
- `WhatTheFlightWatchWidgets/`: complications (circular, corner, rectangular, inline). Timelines dead-reckon traffic one minute at a time for five minutes (`NearbyTraffic.projectedSnapshots`), then show "Open to refresh".
- Siri on the Watch: `WatchWhatsOverheadIntent` (shares `SpokenTraffic.siriAnswer` with iOS) and `FindThatPlaneIntent`.
- Watch launch arguments: `-wtf.demoTraffic YES`, `-wtf.radius 20`; DEBUG builds also accept `-wtf.debugScreen detail|find|identify|nearby|settings|notification`, `-wtf.debugFocus <flight>`, `-wtf.debugPointing <azimuth>,<elevation>` (fake arm direction in the simulator), `-wtf.debugTurn 0|90|180|270` (force the arm-out screen's rotation) and `-wtf.debugNotifications YES` (asks for notification permission so `xcrun simctl push` works).
- Build: `xcodebuild -project WhatTheFlight.xcodeproj -scheme WhatTheFlightWatch -destination 'generic/platform=watchOS Simulator' build`.

Note: legacy type names (`TVSettingsView`, `TVCoordinateEntryView`, `TVSidebarButtonStyle`…) still exist in `Views/tvOSComponents.swift`, so new TV types use different names.

Core tests: `cd WhatTheFlight && swift test` (uses `WhatTheFlight/Package.swift`, which compiles only the platform-neutral files plus `WhatTheFlightTests/Radar/`). The Xcode test targets currently do not compile because of pre-existing errors in the legacy test files.

Handy launch arguments (any `wtf.*` setting can be overridden): `-wtf.demoTraffic YES`, `-wtf.hasSeenWelcome YES`, `-wtf.radius 30`; DEBUG builds also accept `-wtf.debugSheet settings|search|detail|welcome|tvlink|logbook|sky` (`-wtf.debugFind YES` makes Sky View guide to the focused flight; `-wtf.debugCapture YES` aims at the nearest aircraft and takes a photo, synthetic in the simulator), `-wtf.debugMapMode route`, `-wtf.debugLargeSheet YES`, `-wtf.debugBadge <id>` (with `-wtf.debugSheet logbook`), `-wtf.debugFocus <flight>` and `-wtf.debugAutoSend YES` (iPhone), plus `-wtf.debugScreen settings|detail|aircraft|logbook|tour` (`-wtf.debugTourPage N` opens the tour, on either platform, at page N; `-wtf.debugBadge <id>` opens a badge page from the logbook, e.g. `airlines`, `types`; `-wtf.debugSighting <id>` opens a sighting's page, add `-wtf.debugLocate YES` for its "Where Is It Now?"; `-wtf.debugAirframe <reg>` opens an airframe's log), `-wtf.debugPane radar|display|about`, `-wtf.debugSpot lat,lon`, `-wtf.debugDock YES`, `-wtf.debugSearch "<query>"` (with `-wtf.debugScreen settings`) and `-wtf.tvFacing <deg>` (tvOS). Ambient map: `-wtf.mapView NO`, `-wtf.tvView map`, `-wtf.mapNorthUp YES`. Running the iPhone and Apple TV simulators side by side with `-wtf.debugSheet tvlink -wtf.debugAutoSend YES` exercises the real Multipeer hand-off.

## Architecture

### Core Structure
- **MVVM Pattern**: Uses ViewModels (`MainViewModel`, `SettingsViewModel`) to manage state and business logic
- **Protocol-Oriented Services**: Service layer abstractions enable testability and dependency injection
- **Platform-Specific UI**: Conditional compilation for iOS/macOS differences using `#if os(macOS)`

### Key Components

#### Models (`WhatTheFlight/Models/`)
- `FlightData.swift`: Core flight data structures with nested types for airline, aircraft, route, and position
- `ConnectionStatus.swift`: Network connection state management
- `GeographicBounds.swift`: Coordinate boundary definitions for monitoring areas
- `NotificationSettings.swift`: User notification preferences
- `DisplayPreferences.swift`: UI customization settings

#### Services (`WhatTheFlight/Services/`)
- `FlightService.swift`: Primary service managing flight data fetching, monitoring, and state
- `NetworkManager.swift`: HTTP client for FlightRadar24 API interactions
- `LocationManager.swift`: Core Location wrapper for user position tracking
- `SettingsManager.swift`: UserDefaults persistence layer

#### ViewModels (`WhatTheFlight/ViewModels/`)
- `MainViewModel.swift`: Central state manager coordinating all services
- `SettingsViewModel.swift`: Settings UI state and persistence

#### Views (`WhatTheFlight/Views/`)
- `ContentView.swift`: Root view coordinator
- `FlightDisplayView.swift`: Primary flight information UI
- `SettingsView.swift`: Configuration interface
- `iOSComponents.swift` / `macOSComponents.swift`: Platform-specific UI components

### Testing Structure
- **Unit Tests**: Service and model testing with mocks in `WhatTheFlightTests/`
- **UI Tests**: Full application flow testing in `WhatTheFlightUITests/`
- **Mocks**: Comprehensive mock implementations for all service protocols

### Key Patterns
- **Service Protocols**: All services implement protocols for testability (`FlightServiceProtocol`, `NetworkManagerProtocol`)
- **ObservableObject**: ViewModels and services use Combine for reactive UI updates
- **Async/Await**: Modern concurrency throughout the networking layer
- **Platform Adaptation**: Conditional compilation and protocol-based platform differences

### FlightRadar24 API Integration
The app uses unofficial FlightRadar24 API endpoints with specific data parsing for the array-based response format. The `FlightService` handles rate limiting, retry logic with exponential backoff, and real-time monitoring with configurable intervals.
